Player Casual Action Script Plan

Document Purpose
This document summarizes the current player casual movement design for the high-speed combat demo.
It is intended as a script implementation reference, based on the animator logic already discussed and the current non-combat animation setup.
This file does not contain pseudocode. It records the requirements, implementation suggestions, and the current animator configuration assumptions.

========================================
1. Design Scope
========================================

Current focus:
- Non-combat movement logic only
- Animator-driven casual movement flow
- Script-side handling for input, timing windows, movement mode switching, turn triggers, and boost stop triggers

Not included in this phase:
- Combat locomotion implementation
- Weapon draw / mode switch presentation
- Jump and slide full gameplay implementation
- Camera-relative locomotion refinement
- Full root motion integration

Current top-level animation flow:
- Spawn
- Grounded
- Casual or Combat selected by CombatMode

This document focuses on the Casual branch.

========================================
2. Casual Movement Requirements
========================================

2.1 Initial Flow
- Player starts in Spawn
- After Spawn, player enters Grounded
- Grounded checks CombatMode
- If CombatMode is false, player enters Casual

2.2 Casual Idle
- Casual_Idle is the resting state inside Casual
- If MoveSpeed or effective movement input is zero, player stays in Casual_Idle
- Casual_Idle is the fallback state when no valid forward or backward movement input is active

2.3 Movement Modes
Casual movement is divided into three modes:
- Walk
- Jog
- Boost

Default mode:
- Jog

Mode switching rules:
- Press Alt to toggle between Jog and Walk
- Press Shift while W or S is held to enter Boost

2.4 Walk Mode
Walk uses two actions:
- Walk_Front when W is held
- Walk_Back when S is held

Walk behavior:
- Enter Walk mode by pressing Alt while in Jog
- If W is pressed, play Walk_Front
- If S is pressed, play Walk_Back
- Press Alt again to return to Jog mode
- If neither W nor S is pressed, return to Casual_Idle

2.5 Jog Mode
Jog uses four actions:
- Jog_Front
- Jog_Back
- Jog_TurnR_180_Left
- Jog_TurnR_180_Right

Jog behavior:
- Jog is the default movement mode
- If W is pressed, play Jog_Front
- If S is pressed, play Jog_Back
- If no forward or backward input is present, return to Casual_Idle

Jog turn behavior:
- Turn actions are transition actions used to reverse direction and continue moving
- If the player holds W for a minimum amount of time
- Then releases W
- Then presses S again inside a short timing window
- A probabilistic trigger selects Jog_TurnR_180_Left or Jog_TurnR_180_Right

Jog turn result:
- Turn state should return to Move_Jog_Back through the existing empty transition
- If HasMoveInput becomes false during the turn, turn state should return to Idle

Additional animator note:
- Direct Move_Jog to Move_Dash_Back transition has been removed intentionally

2.6 Boost Mode
Boost uses:
- Mvm_Dash
- Mvm_Dash_Back
- Mvm_Stop_Front
- Mvm_Dash_TurnR_180_Left
- Mvm_Dash_TurnR_180_Right

Boost entry behavior:
- Boost can be entered only while W or S is currently held
- If the current mode is Walk or Jog and Shift is pressed:
  - W + Shift enters Mvm_Dash
  - S + Shift enters Mvm_Dash_Back

Boost forward behavior:
- While in Mvm_Dash, holding W continues the forward dash
- Releasing Shift during forward dash should return player to Jog mode
- After staying in Mvm_Dash for a minimum duration, releasing W should trigger Mvm_Stop_Front
- After Mvm_Stop_Front finishes, player returns to Casual_Idle

Boost turn behavior:
- If player has been in Mvm_Dash for a minimum duration
- Then releases W
- Then presses S again within a short timing window
- A probabilistic trigger selects Mvm_Dash_TurnR_180_Left or Mvm_Dash_TurnR_180_Right

Boost turn result:
- Turn state should return to Move_Dash_Back through the existing empty transition
- If HasMoveInput becomes false during the turn, turn state should return to Idle

========================================
3. Current Animator Configuration Summary
========================================

This section records the current intended animator behavior based on the latest design discussion.

3.1 Base Layer Structure
- Spawn
- Grounded
- Casual
- Combat

Expected flow:
- Entry -> Spawn
- Spawn -> Grounded
- Grounded -> Casual when CombatMode == false
- Grounded -> Combat when CombatMode == true

3.2 Casual State Set
Expected states inside Casual:
- Casual_Idle
- Walk_Front
- Walk_Back
- Jog_Front
- Jog_Back
- Jog_Turn180_Left
- Jog_Turn180_Right
- Dash_Front
- Dash_Back
- Dash_Stop_Front
- Dash_Turn180_Left
- Dash_Turn180_Right

3.3 Animator Parameters
Current expected parameters:

Bool:
- CombatMode
- HasMoveInput

Int:
- MoveMode
- TurnVariant

Float:
- MoveY

Trigger:
- Turn180
- BoostStop

MoveMode meaning:
- 0 = Walk
- 1 = Jog
- 2 = Boost

TurnVariant meaning:
- 0 = Left
- 1 = Right

MoveY meaning:
- 1 = Forward input
- -1 = Backward input
- 0 = No forward/backward input

3.4 Turn State Configuration
Current turn-state rule:
- Each of the four turn states has two transitions
- One empty transition returns to the related movement state
- One HasMoveInput == false transition returns to Idle

Turn return mapping:
- Jog_Turn180_Left -> Jog_Back
- Jog_Turn180_Right -> Jog_Back
- Dash_Turn180_Left -> Dash_Back
- Dash_Turn180_Right -> Dash_Back

This matches the design goal that turn states are directional continuation actions, not standalone locomotion states.

3.5 Removed Transition
- Direct Move_Jog -> Move_Dash_Back transition has been removed

Reason:
- This avoids an unnatural direct jump from regular jog state into backward dash state
- Backward dash should only be entered through the explicit boost input path

========================================
4. Script Responsibility
========================================

The player action script should not try to let Animator decide all gameplay logic.
The intended split is:

Animator should handle:
- Which animation state is currently playing
- Transition playback between states
- Returning from turn states to the related locomotion state
- Returning to idle when HasMoveInput is false

Script should handle:
- Reading player input
- Tracking Walk, Jog, and Boost mode
- Deciding when Alt toggles Walk and Jog
- Deciding when Shift enters or exits Boost
- Tracking forward hold duration
- Tracking release timing windows
- Detecting turn trigger opportunities
- Selecting turn variant randomly
- Triggering Turn180
- Triggering BoostStop
- Driving actual character movement and facing
- Writing animator parameters every frame

Important implementation rule:
- Timing windows and turn probability should stay in script
- They should not be implemented through complex animator-only condition chains

========================================
5. Recommended Script Implementation Direction
========================================

Recommended first-pass architecture:
- One main player casual movement script is enough for the current demo phase

Suggested file direction:
- PlayerCasualController or similarly named script

Why a single script is recommended first:
- The current project has almost no player gameplay code yet
- The demo needs fast iteration on movement feel
- Mode switching and timing windows are tightly connected
- A single implementation is easier to tune before later refactoring

Future refactor direction if needed:
- Input reader
- Locomotion motor
- Animator driver
- Casual state controller

========================================
6. Input Interpretation Suggestions
========================================

Current movement logic only requires reliable handling of:
- W
- S
- Alt
- Shift

Suggested meaning:
- W = forward move intent
- S = backward move intent
- Alt = toggle between Walk and Jog
- Shift = enter or maintain Boost while directional input is valid

Important note:
- Boost should only start when W or S is already active
- Turn180 checks should use actual input timing, not only animator state

========================================
7. Recommended Runtime Data To Track In Script
========================================

The action script should maintain enough runtime data to reproduce the intended movement behavior.

Recommended tracked values:
- Current movement mode
- Current forward/backward input value
- Whether the player currently has movement input
- Whether the player is currently in a turn sequence
- Whether the player is currently in combat mode
- Forward hold duration for Jog turn checks
- Timestamp of forward release for Jog turn window
- Timestamp of Boost start
- Timestamp of forward release during forward dash
- Previous-frame key states for W, S, Alt, and Shift

Reason:
- The design depends on press, release, re-press, and timing windows
- Those are easier and safer to evaluate in script than in Animator

========================================
8. Recommended Tunable Timing Values
========================================

These values should be serialized in the script for tuning in Inspector:

- Walk speed
- Jog speed
- Boost speed
- Acceleration
- Rotation speed
- Minimum W hold duration required before Jog turn can be triggered
- Jog turn input window after releasing W
- Minimum Boost duration before forward dash can stop
- Boost turn window after releasing W
- Minimum Boost duration before stop animation is allowed

Reason:
- The demo's feel depends heavily on timing and responsiveness
- These values will likely need repeated tuning during testing

========================================
9. Implementation Behavior Notes
========================================

9.1 Walk / Jog Toggle
- Alt should switch Walk and Jog modes
- This toggle should not interrupt active turn sequences
- It should generally be ignored while already in Boost

9.2 Boost Entry
- Shift alone should not trigger Boost
- A directional intent must already be present
- Forward and backward Boost should be distinguished by current input direction

9.3 Forward Boost Stop
- Mvm_Stop_Front should only be triggered from forward dash
- It should only be allowed after a minimum dash duration
- Stop trigger should be fired by script, then Animator handles playback

9.4 Turn Triggering
- Jog turns and Dash turns should both be script-triggered
- The script should assign TurnVariant before triggering Turn180
- The random left or right selection should be script-side

9.5 Turn Completion
- Since the animator is already configured so turn states return to movement or idle, script does not need to force the return state directly
- Script only needs to avoid conflicting movement logic while the turn animation is active

========================================
10. Practical Development Priorities
========================================

Recommended order for implementation:

1. Make Spawn -> Grounded -> Casual stable
2. Make Idle / Walk / Jog stable
3. Make Alt Walk-Jog toggle stable
4. Make Shift enter forward and backward Boost
5. Make forward Boost release trigger Stop_Front
6. Make Jog turn detection stable
7. Make Dash turn detection stable
8. Add movement polish, turn lock rules, and visual tuning

Reason:
- This order lets the basic locomotion loop become testable as early as possible
- Turn timing should be implemented only after normal movement transitions feel correct

========================================
11. Current Conclusion
========================================

The current animator structure is suitable for the planned casual movement demo if the gameplay logic stays script-driven.
The strongest implementation approach is:
- Use Animator as the playback and transition layer
- Use script as the source of truth for input timing, movement mode, turn triggering, and stop triggering

This keeps the movement logic readable, tunable, and easier to extend later into combat mode.
