Combat System Design Notes

Document Purpose
This document records the current agreed combat system design for the high-speed ground-based action prototype.
The design avoids air-combat as a core loop, reduces command complexity, and builds combat around Focus and Stagger.
This file is intended to serve as the shared baseline before configuring the combat animator and writing the combat input script.

========================================
1. High-Level Combat Direction
========================================

The combat system is intended to be:
- ground-focused
- high-speed
- low command complexity
- high decision density

The combat should avoid:
- air combat as a core gameplay loop
- complex command strings / command mashing
- large move lists that force the player to memorize too many input sequences

The combat should emphasize:
- pressure
- timing
- interruption
- stagger buildup
- controlled burst windows
- strong offensive and defensive decision-making

========================================
2. Core Combat Pillars
========================================

The current combat system is built around four pillars:

1. Basic offense
- Light attack chain
- Heavy attack
- Run attack

2. Defensive reaction
- Dodge
- Guard
- Timed parry
- Counter attack

3. Enemy pressure loop
- Stagger buildup
- Stagger break
- Vulnerable window
- Execution window

4. Player resource loop
- Focus gauge
- Resource spending
- Burst timing

========================================
3. Focus System
========================================

Focus is the player's main combat resource.
It creates:
- player initiative
- action priority
- an economy for stronger attacks

Focus capacity:
- Focus is divided into 3 segments
- Each segment is a meaningful spend unit

Current Focus intent:
- 1 segment = standard heavy attack

Focus generation:
- Light attack hit: +0.25
- Run attack hit: +0.5
- Heavy attack hit: +0.1
- Perfect dodge: +0.5
- Perfect dodge followed by successful punish shortly after: additional +0.5
- Successful parry: +1
- Successful parry counter hit: additional +0.5
- Execution: +1
- Effective follow-up on staggered enemy: +0.25

Focus recovery rules:
- No passive auto-recovery during combat
- Focus must be earned by successful combat actions

Dodge relationship to Focus:
- Normal dodge gives no Focus
- Perfect dodge gives partial Focus
- Additional reward is granted if the player actually punishes

Parry relationship to Focus:
- Regular guard gives no Focus
- Timed parry gives large Focus reward
- Counter hit after parry grants additional reward

Focus when full:
- Full Focus should not feel wasted
- Higher-value offensive options should become available when more Focus is stored

Recommended current tier structure:
- 1 Focus: standard heavy attack
- 2 Focus: stronger heavy / higher stagger / stronger break attack
- 3 Focus: special high-value finisher / wave attack

Out-of-combat Focus behavior:
- Focus should not be permanently banked between encounters
- Focus starts decaying 2 seconds after leaving combat
- Focus decays at 1 segment per second
- Minimum retained Focus after full decay: 0

Design intention:
- Focus is a combat rhythm resource, not a preparation resource

========================================
4. Stagger System
========================================

Stagger is the enemy-side pressure resource.
It is not a universal identical bar for every enemy.

Enemy grouping:
- Small enemies share one type of stagger logic
- Elite enemies share one type of stagger logic
- Bosses share one type of stagger logic

Stagger accumulation:
- All player actions that successfully affect enemies can build stagger
- Stagger should generally persist rather than constantly reset
- The system should reward both high-skill players and less experienced players

Design goal:
- Skilled players can rapidly force stagger through parry, pressure, and burst
- Less experienced players can still slowly build toward stagger through steady combat

Stagger break result:
- Enemy action is interrupted
- Enemy enters a vulnerable state
- Execution and burst opportunities become available

Execution by enemy type:
- Small enemy:
  - execution kills instantly
- Elite enemy:
  - execution deals major execution damage but does not instantly kill
- Boss:
  - execution or critical punish deals major damage but is not an instant kill

Stagger window purpose:
- Provide a punishment phase
- Allow execution opportunity
- Allow stored Focus to be converted into burst damage

Vulnerability during stagger:
- Staggered enemies should take bonus damage
- This is necessary to create a strong positive reward for risky skillful play

Design reason:
- If stagger does not meaningfully increase payoff, high-risk behaviors such as parry and aggressive pressure lose value

========================================
5. Relationship Between Focus And Stagger
========================================

The combat loop depends on the interaction of:
- Player Focus
- Enemy Stagger

Player-side logic:
- Build Focus through smart offense and defense
- Spend Focus on higher-value actions

Enemy-side logic:
- Build enemy stagger through sustained pressure
- Break enemy posture / stability
- Convert stagger into executions or burst windows

Shared combat loop:
- Use light attacks and run attacks to pressure and build Focus
- Use heavy attacks and high-value actions to accelerate stagger
- Use dodge or parry to stay in tempo and gain better resource efficiency
- Force stagger
- Spend stored Focus during the vulnerability window
- Use execution when appropriate

========================================
6. Offensive Move Roles
========================================

The current action assets should not be treated as many unrelated parallel combo trees.
They should be reorganized by combat purpose.

Recommended offensive role categories:

1. Basic light attack chain
- Primary default offense
- Safe pressure
- Main Focus builder
- Main low-to-mid stagger builder

2. Heavy attack / break attack
- Focus spender
- Higher stagger value
- Stronger interruption potential
- Used to break defense or push into stagger faster

3. Run attack
- Engagement tool
- Tempo reset tool
- Pressure entry
- Medium Focus / medium-to-high stagger value

4. Counter attack
- High-reward skill response after successful parry
- Strong stagger value
- Strong tempo swing

5. Wave / finisher attack
- Higher-tier Focus spending branch
- Not a basic light attack
- Not a cheap spam action
- Intended as a high-value offensive conversion tool

========================================
7. Wave Attack Role
========================================

Wave attack should not be classified as a standard light attack.
It should be treated as a special offensive finisher.

Current role:
- Special finisher
- Advanced heavy-branch spender
- Safe or ranged ender
- Strong stagger conversion or burst conversion tool

Current design direction:
- Wave attack should be tied to Focus
- It should preferably belong to the high-value end of the resource system

Recommended current relation to Focus:
- Prefer 3 Focus for the true full wave version
- Lower-tier fallback behavior can be added later if desired

Design reason:
- Prevent wave attack from becoming a low-cost spam tool
- Preserve Focus as an action-priority resource

========================================
8. Defensive Move Roles
========================================

The defense side of combat is currently intended to be split clearly.

Dodge:
- Main evasive safety tool
- Fast, responsive, lower reward than parry
- Perfect dodge creates resource advantage

Guard:
- Main safe defensive hold
- No Focus generation by default

Parry:
- High-risk, high-reward timing defense
- Strong Focus gain
- Strong tempo reversal potential

Parry counter:
- Direct reward after successful parry
- Offensive swing action
- Strong stagger effect

========================================
9. Enemy State Results
========================================

The enemy should broadly move through these pressure states:

1. Normal combat state
- Can attack freely
- Standard stagger behavior

2. Near-break pressure state
- Enemy stagger gauge is close to break
- Player decides whether to continue safe pressure or spend Focus

3. Stagger break
- Enemy action interrupted
- Vulnerability triggered
- Execution window opens

4. Vulnerable state
- Enemy takes bonus damage
- Player can spend stored Focus efficiently
- Small enemies may be executed immediately

5. Recovery or death
- Small enemies usually die from execution
- Elite/Boss return to combat after punishment unless defeated

========================================
10. Current Input Philosophy
========================================

The system should avoid complex command execution.

The intended philosophy is:
- Simple inputs
- Strong context
- Meaningful decision-making

Current intended input directions:
- Light attack should remain simple and consistent
- Heavy attack should be a resource-aware commitment action
- Run attack should be a movement-context action
- Dodge should remain direct and readable
- Guard / parry should depend on timing rather than command complexity
- Execution should be a contextual state action

========================================
11. Current First-Version Combat Structure
========================================

The current first-version combat prototype should be built around:

- Light attack chain
- Heavy attack
- Run attack
- Dodge
- Guard
- Timed parry
- Parry counter
- Stagger break
- Execution
- Wave / finisher attack

Optional advanced actions can be layered in later, but these form the core.

========================================
12. Combat Design Summary
========================================

The current agreed combat design is:

- Ground-focused high-speed action combat
- Low command complexity
- Strong pressure and response gameplay
- Player-side Focus resource with 3 segments
- Enemy-side Stagger resource with enemy-type grouping
- Focus is used to prioritize stronger offense
- Stagger is used to create break, execution, and burst windows
- Staggered enemies are more vulnerable to damage
- Small enemies can be executed to death
- Elites and bosses take execution damage instead of instant death
- Wave attack is a higher-tier finisher, not a basic attack

This document is now the current baseline for the combat system before animator setup and combat script implementation.
